# Remote Work Policy — Version 1

## 1. Purpose and scope

This version describes remote work at Atlas Services, a fictional Moroccan company, for tasks that can be performed remotely. The employee and line manager maintain service coverage and agree on how the employee will be available.

## 2. Requests and authorization

The employee tells the line manager the requested day, planned tasks, and how they can be contacted. The line manager checks whether the tasks can be performed remotely and whether service coverage can be maintained.

**Conditional approval.** If the tasks and service coverage allow it, the line manager may authorize a maximum of one remote-work day per week in advance.

The employee waits for written approval before working remotely. Any change of day goes to the line manager before it takes effect.

## 3. Tracking arrangements

| Party | Responsibility | Information to record |
|---|---|---|
| Employee | Submit the request and report changes | Requested day, tasks, and contact arrangements |
| Line manager | Check service coverage and decide | Authorized day, decision, and date |
| HR | Retain decisions sent by line managers | Copy of the approval and any changes |

## 4. Data protection and interruptions

Atlas Services' data handling rules also apply to remote work. Employees use approved tools and storage spaces, share data only with authorized recipients, and report incidents through the designated internal channel. If an interruption prevents remote work, the employee tells the line manager so they can agree on an alternative arrangement.

## 5. Temporary exception

**Exception.** If a temporary need is justified, the line manager may authorize an additional day after consulting HR and before the arrangement begins.

The line manager records the reason, dates covered, and planned service coverage, then sends the decision to HR. When the exception ends, the employee returns to the ordinary arrangement.
